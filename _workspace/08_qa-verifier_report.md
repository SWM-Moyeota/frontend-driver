## 환경 특이사항 (중요)

기존 에뮬레이터 emulator-5554(Pixel_6)에서는 **승객 앱(com.moyeota)이 반복적으로 전면을 탈취**했고, 검증 도중 기사 앱 패키지가 `enabled=3`(user-disabled)로 바뀌는 이벤트까지 발생 — 외부 프로세스(승객 앱 검증 세션으로 추정)가 같은 에뮬레이터를 사용 중인 것으로 판단된다. 지침에 따라 해당 프로세스는 죽이지 않고, **새 AVD `Pixel_6_QA`(port 5558)를 생성해 재검증**했다. 이후 전 플로우가 방해 없이 재현됐다.
주의: 5554에서 제 입력 탭 일부가 승객 앱으로 전달됐다(승객 앱 더미 상태가 변경됐을 수 있음).

## 결함 목록

### M-1 (중간) D05b 「영업 시작하기」가 홈(휴무)로 진입 — 스펙은 홈(영업중)
- 위치: `presentation/src/main/kotlin/com/moyeota/driver/presentation/feature/auth/AuthGraph.kt:61~66` (`onStartDuty`가 `navigate(HOME)`만 수행, `setDutyStatus(true)` 미호출)
- 재현: 가입 완료 → D05b → 「영업 시작하기」 → 홈이 「휴무」 배지(D06)로 렌더
- 스펙: 「영업 시작하기」 → 07 홈(영업중) (위치 권한 미허용 시에만 06)
- 스크린샷: scratchpad/after_d05b.png (홈 휴무 상태)
- 담당: compose-builder(auth). 권한 처리 미도입 상태이므로 최소한 duty ON 시도 후 이동하거나, 미구현 사유를 산출물에 명시 필요

### M-2 (중간) D14 「운행 시작」 활성 조건이 스펙과 불일치
- 위치: `presentation/src/main/kotlin/com/moyeota/driver/presentation/feature/trip/BoardingScreen.kt:251` — `enabled = allProcessed && boardedCount >= 1`
- 재현: 승객 2명 중 1명만 코드 확인(탑승) → 「운행 시작」 여전히 비활성. 전원 처리 후에만 활성
- 스펙: "탑승 확인 1명 이상일 때만 「운행 시작」 활성" — 나머지 승객이 대기 중이어도 활성이어야 하는지, 노쇼 처리 강제가 맞는지 해석 차이. 전원 처리 강제는 대기 승객 방치를 막는 합리적 설계이나 스펙 문구와 다름 → 스펙 재확인 또는 조건 완화 필요
- 담당: compose-builder(trip) + 리더 스펙 판단

### m-1 (경미) D08 「조금 더 운행」 버튼 텍스트 2줄 줄바꿈
- 위치: `presentation/src/main/kotlin/com/moyeota/driver/presentation/feature/home/OffDutyConfirmRoute.kt:219` (좌측 보조 CTA 폭 부족)
- 재현: D07 「영업 종료」 → D08 좌하단 버튼이 「조금 더 운\n행」으로 꺾임 (qa/D08.png)
- 공통 규칙 "문구는 한 줄 3어절 이내" 취지 위반. 버튼 최소 폭 확대 또는 `maxLines=1` + 문구 축약(「더 운행」) 권장
- 담당: compose-builder(home)

### m-2 (경미/기지) 운행 중 프로세스 종료 후 재실행 시 D01로 복귀 — 운행 단계 복구 없음

- 담당: 리더/api-integrator (실연동 시)
