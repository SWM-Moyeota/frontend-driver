# 33. QA 결함 수정 계약 (L1~L4 종합)

## 수정 대상 (근거: 32a·32b·32d)

### F1. 리포지토리 메시지가 화면에 안 닿는다 — **최우선** (32b D-1, D-4)
- `LoginScreen.kt:74-76` 이 `catch (e: Exception)` 에서 **고정 문구**("아이디 또는 비밀번호가 맞지 않아요")를 쓴다.
  리포지토리가 만든 `"서버에서 택시 서비스가 꺼져 있어요 · 운영자에게 문의해 주세요"` 가 버려진다.
  → `e.message` 를 우선 노출하고, 비어 있을 때만 기존 문구로 폴백한다.
- `HomeRoute.kt:127-131` 영업 시작 실패도 동일 — 서버에 기능이 없는데 "다시 시도해 주세요"는 영원히 통하지 않는다.
  → `e.message` 우선 노출(이미 있는 `DriverLocationUnavailableException` 분기는 유지).

### F2. 기사 기능 비활성 상태에서 홈이 "정상"처럼 보인다 (32a D4, 32b D-2)
로그인 토큰은 저장돼 있고 복구는 성공하므로 다음 실행에 홈에 착지하는데, 홈 요약이 더미라
기사는 "콜이 안 오는 멀쩡한 홈"을 본다.
→ **홈 진입 시 `repository.isTaxiServiceEnabled()` 를 확인해 false 면 경고 배너**를 띄운다
  (문구 예: "서버에서 기사 기능이 꺼져 있어요 · 지금은 콜을 받을 수 없어요").
  영업 시작 CTA 는 눌러도 어차피 실패하므로 비활성화하거나 배너와 함께 둔다(판단은 compose-builder).
**토큰 보존 정책은 유지한다** — 서버가 복구되면 재로그인 없이 이어서 쓰는 게 맞고, F1·F2 로 화면이 솔직해지면 혼란이 없다.
(그래서 32d 가 제안한 "로그인 실패 시 세션 비우기" 테스트는 **채택하지 않는다**.)

### F3. 제출 실패 시 유효한 인증 토큰을 버린다 (32a 상위 1번)
백엔드는 가입이 **완전히 성공한 뒤에만** 토큰을 소비한다(`LocalUserService` 주석·코드로 확인).
그런데 클라는 제출 실패 시 토큰을 버리고 `codeSent=false`·쿨다운 0 으로 되돌려 재발송을 유도 →
서버 쿨다운 60초에 걸려 **429(USER202)** + 일일 5통 중 1통 소모.
→ 제출이 실패해도 **받은 토큰과 쿨다운 상태를 유지**하고, 사용자는 「다시 제출」로 재시도한다.
  토큰 만료(USER207 류)로 실패했을 때만 재발송 경로를 연다.

### F4. 발송 실패 화면의 문구 충돌 (32b D-3)
`PhoneCodeStep.kt:52` 부제가 `codeSent` 와 무관해, 발송 실패 화면에서
"…인증번호를 보냈어요" 와 "보내지 못했어요" 가 동시에 보인다. → 부제를 상태 기반으로.

### F5. 주석 정정 (32d)
`RemoteDriverRepository.kt:202-203` 주석이 `DRIVER_NOT_FOUND` 도 확인된 종료라고 적었지만
실제 판정(`isDriverMissing`)은 `DRIVER_NOT_REGISTERED` 만 본다(판정이 옳다). 주석에서 제거.

## 범위 밖 (후속 과제로 기록)
- **기존 승객 계정 → 기사 전환 경로 부재**(32a 상위 3번): 기가입 번호는 문자 발송이 409 로 막히고,
  로그인해도 기사 미등록이라 현 가입 화면만으로는 전환 불가. "로그인 후 기사 등록만 진행하는 흐름"이
  필요하며 화면 신설이 따르므로 별도 PR 로 다룬다.
- `presentation/src/test` 소스셋 신설(32a·32d 권고) — 빌드 설정 변경이라 별도 PR.
